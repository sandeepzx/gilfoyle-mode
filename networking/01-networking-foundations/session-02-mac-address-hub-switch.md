# Networking — Session 2
## Ethernet, MAC Addresses, Ethernet Frames, Hubs, and Switches

---

## 1. Ethernet

### What is Ethernet?

Ethernet is a family of networking technologies and rules used to communicate over wired local area networks (LANs).

It defines how devices communicate over Ethernet links, including the structure of Ethernet frames and how network interfaces transmit and receive data.

Ethernet is **not the same thing as an Ethernet cable**.

- **Ethernet:** The communication technology and rules.
- **Ethernet cable:** The physical medium that carries signals.
- **NIC:** The network interface that connects a device to the network.

These components work together to enable communication.

### Why do we need a special Ethernet cable?

Ethernet cables commonly contain eight copper conductors arranged into four twisted pairs.

Ethernet cables are designed to control electrical characteristics such as impedance, signal loss, and interference between conductors.

Twisting the wires in each pair helps reduce electromagnetic interference and crosstalk. Ethernet interfaces also use signaling techniques designed for reliable data transmission.

## 2. MAC Addresses

### What is a MAC address?

A MAC address (Media Access Control address) is an identifier used by a network interface for communication at the Ethernet layer.

For example:

`3C:52:82:AB:CD:EF`

A standard Ethernet MAC address is 48 bits long.

It is commonly written as six groups of hexadecimal digits:

`3C : 52 : 82 : AB : CD : EF`

Each group represents one byte (8 bits).

Therefore:

- 6 bytes × 8 bits = 48 bits
- Each byte is represented by two hexadecimal digits.

### Relationship between a NIC and a MAC address

A NIC (Network Interface Card) provides a network interface through which a device connects to a network.

A MAC address is an identifier associated with that interface. It is not a separate physical component attached to the NIC.

For example, a computer might have:

- An Ethernet interface with one MAC address.
- A Wi-Fi interface with another MAC address.

These interfaces provide different ways to connect to networks, so they can have different MAC addresses.

### Who assigns a MAC address?

Typically, the manufacturer assigns a factory MAC address to the interface during manufacturing or production provisioning.

For universally administered MAC addresses, the organization is assigned an address range, and the manufacturer assigns individual addresses from that range.

For example, a manufacturer might assign illustrative addresses such as:

- `3C:52:82:00:00:01`
- `3C:52:82:00:00:02`
- `3C:52:82:00:00:03`

The different addresses help distinguish the interfaces.

A MAC address is not normally generated by the router when the device connects to a network.

### Can a MAC address be random?

Yes.

Some operating systems use MAC address randomization, especially for Wi-Fi privacy.

An interface may have a factory-assigned MAC address but use a different, locally administered address when connecting to a particular network.

A MAC address can also sometimes be changed through software configuration.

## 3. Ethernet Frames

### What is an Ethernet frame?

An Ethernet frame is a structured unit of data used for communication over an Ethernet link.

When a computer sends data over Ethernet, the networking stack and NIC work together to prepare and transmit an Ethernet frame.

The frame contains addressing information, control information, payload data, and error-checking information.

Think of it like a parcel: the addressing information helps identify the intended receiver, while the payload is the content being carried.

### Structure of an Ethernet frame

A simplified Ethernet frame contains the following fields:

| Field | Purpose |
|---|---|
| Destination MAC | Identifies the intended destination interface |
| Source MAC | Identifies the sending interface |
| Type / Length | Identifies the payload protocol in Ethernet II, or represents payload length in other Ethernet formats |
| Payload | Carries the data, often an IP packet |
| FCS | Frame Check Sequence, used for error detection |

The standard Ethernet frame also has a preamble and start-frame delimiter transmitted before the frame itself. These help the receiver synchronize with the incoming transmission.

### Destination MAC address

The destination MAC address identifies the interface the frame is intended to reach.

For example, if Computer A sends a frame to Computer B, the destination MAC field normally contains B's MAC address when B is the intended local Ethernet destination.

### Source MAC address

The source MAC address identifies the interface that transmitted the frame.

If Computer A sends a frame, the source MAC field normally contains A's MAC address.

### Payload

The payload contains the data being carried by the frame.

It is not necessarily plain text. Often, the payload contains a network-layer packet, such as an IP packet.

### FCS — Frame Check Sequence

The FCS contains a value used to detect certain transmission errors.

The receiving interface can check the FCS to determine whether the frame appears to have been corrupted.

FCS helps detect errors; it does not itself correct the corrupted data.

### Frame versus packet

A frame and a packet are different networking units.

- **Frame:** Used at the Ethernet layer for communication across an Ethernet link.
- **Packet:** Commonly refers to the network-layer unit, such as an IP packet, carried inside the frame.

An Ethernet frame can carry an IP packet as its payload.

## 4. How Data Travels Through Ethernet

Understanding the complete process connects the NIC, MAC address, frame, and cable.

### Sending process

Suppose Computer A wants to send data to Computer B.

1. Computer A's networking software prepares the data for transmission.
2. The networking stack and NIC work together to prepare the Ethernet frame.
3. The frame contains the source MAC address, destination MAC address, payload, and FCS.
4. The NIC's transmission circuitry converts the frame's bits into physical signals.
5. The Ethernet cable carries those signals to the connected device.

### Receiving process

At the receiving end:

1. The receiving interface detects the incoming physical signals.
2. Its physical-layer circuitry recovers the transmitted bits.
3. The interface processes the bits as an Ethernet frame.
4. The frame is checked and filtered according to the interface's capabilities and configuration.
5. Accepted frames can be passed to the networking stack for further processing.
6. The networking stack processes the payload and delivers data to the appropriate protocol or application.

The NIC does not necessarily accept every frame for further processing. For example, a normal unicast frame addressed to another interface is generally filtered out.

### The complete mental model

**Data → Ethernet frame → physical signals → cable → received signals → recovered bits → frame processing → payload processing**

The physical signals are what travel through the cable. The Ethernet frame is the structured data represented by those signals.

## 5. Hubs

### What is a hub?

A hub is a basic networking device that connects multiple devices in a LAN.

A traditional Ethernet hub operates at **OSI Layer 1 — the Physical layer**.

Its job is to repeat incoming physical signals through its other ports.

### How does a hub work?

Suppose Computers A, B, and C are connected to a hub.

Computer A sends an Ethernet frame intended for Computer B.

1. A's NIC transmits the frame as physical signals.
2. The hub receives those signals.
3. The hub repeats the signals through its other ports.
4. B and C receive the repeated signals.
5. Their NICs process the incoming transmission and normally filter out a unicast frame that is not intended for them.

The hub does not inspect the destination MAC address to choose an output port.

It does not remove the MAC addresses and send only the payload. Instead, it repeats the physical representation of the transmission.

A hub does not operate like a switch that reconstructs and examines Ethernet frames for forwarding decisions.

### Why are hubs inefficient?

A hub repeats signals to the other ports regardless of the destination MAC address.

This means devices receive transmissions that may not be intended for them.

Traditional hubs also share a collision domain, so simultaneous transmissions can interfere with one another.

## 6. Network Switches

### What is a switch?

A network switch connects multiple devices in a LAN and forwards Ethernet frames using MAC addresses.

A traditional Ethernet switch operates at **OSI Layer 2 — the Data Link layer**.

Unlike a hub, a switch processes Ethernet frames and can selectively forward them to the appropriate ports.

### Does a switch have network interfaces?

Yes. A switch has Ethernet interfaces on its ports, with physical-layer circuitry to transmit and receive signals and MAC-layer logic to process frames.

A switch is not usually built like a desktop computer with a separate ordinary NIC card for each port. It typically uses specialized hardware, often integrated into switching chips.

A simplified view of its internal operation is:

1. A switch port receives physical signals.
2. The physical-layer circuitry recovers the bits.
3. The switch processes the incoming Ethernet frame.
4. The switch examines the source and destination MAC addresses.
5. Its switching logic determines how to forward the frame.

### The MAC address table

A switch maintains a MAC address table, also called a forwarding table.

The table maps learned MAC addresses to switch ports.

For example:

| MAC address | Switch port |
|---|---|
| `AA:AA:AA:AA:AA:AA` | Port 1 |
| `BB:BB:BB:BB:BB:BB` | Port 2 |
| `CC:CC:CC:CC:CC:CC` | Port 3 |

This table helps the switch determine which port leads to a particular MAC address.

### How does a switch learn MAC addresses?

A switch learns from the **source MAC address** of incoming frames.

Imagine Computer A is connected to Port 1 and sends a frame.

1. The switch receives the frame on Port 1.
2. It reads the source MAC address.
3. It learns that the source MAC address is reachable through Port 1.
4. It looks up the destination MAC address in its forwarding table.
5. Depending on the lookup result, it decides how to forward the frame.

Switches maintain these learned entries dynamically, and entries can age out if they are not refreshed.

### What if the destination MAC address is known?

If the destination MAC address is in the forwarding table, the switch normally forwards the frame through the associated port.

If the destination is associated with the same port on which the frame arrived, the switch normally does not forward that frame back out the same port.

### What if the destination MAC address is unknown?

If the switch does not have an entry for an unknown unicast destination, it normally floods the frame through the other eligible ports in the same VLAN, excluding the incoming port.

If the switch later receives a frame sourced from that destination MAC address, it can learn the destination's location from that frame.

Flooding an unknown unicast frame is different from what a hub does. A switch processes the frame and applies its forwarding rules, while a hub simply repeats physical signals.

### Switch summary

- Operates at Layer 2 in a traditional Ethernet LAN.
- Receives physical signals and processes Ethernet frames.
- Learns source MAC addresses and their associated ports.
- Uses the destination MAC address to make forwarding decisions.
- Forwards known unicast frames selectively.
- Normally floods unknown unicast frames through eligible ports in the same VLAN.

## 7. Hub vs Switch

| Feature | Hub | Switch |
|---|---|---|
| Traditional OSI layer | Layer 1 | Layer 2 |
| Main job | Repeats physical signals | Forwards Ethernet frames |
| Examines MAC addresses | No | Yes |
| Learns MAC-to-port mappings | No | Yes |
| Known unicast forwarding | Repeats signals to other ports | Normally forwards through the destination port |
| Unknown unicast handling | Repeats signals to other ports | Normally floods to eligible ports in the same VLAN |
| Collision domain | Shared | Each port is a separate collision domain in ordinary switched Ethernet |
| Efficiency | Lower | Higher |

## 8. Quick Revision

### Remember these relationships

- **Ethernet:** Networking technology and communication rules.
- **Ethernet cable:** Physical medium that carries signals.
- **NIC:** Network interface that transmits and receives network data.
- **MAC address:** Identifier associated with a network interface.
- **Ethernet frame:** Structured data unit containing MAC addresses, payload, and error-checking information.
- **Hub:** Repeats physical signals without inspecting destination MAC addresses.
- **Switch:** Processes Ethernet frames and forwards them using MAC address information.

### Trace a frame through a switch

When Computer A sends a frame to Computer B:

1. A's networking stack and NIC prepare and transmit the frame.
2. The cable carries physical signals to the switch.
3. The switch's physical-layer circuitry recovers the bits.
4. The switch processes the frame and learns A's source MAC address on the incoming port.
5. The switch checks its forwarding table for B's destination MAC address.
6. If B's MAC address is known, the switch normally forwards the frame through B's port.
7. B's NIC receives the signals, processes the frame, and passes accepted data to the networking stack.

If B's MAC address is unknown, the switch normally floods the frame through other eligible ports in the same VLAN.

### One-line mental model

**The NIC transmits and receives Ethernet data, the cable carries physical signals, the frame contains the addressing information, a hub repeats signals, and a switch uses MAC addresses to forward frames.**
